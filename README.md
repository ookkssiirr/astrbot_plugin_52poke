## 📖 简介

`astrbot_plugin_52poke` 为 AstrBot 提供基于 [神奇宝贝百科 (52poke)](https://wiki.52poke.com/) 的按需事实检索能力。

当涉及最新世代宝可梦设定、新招式、特性、道具调整，或精确种族值（包括普通、Mega 与超级进化 Z 形态）时，大模型可在对话中自主调用本工具，检索权威数据并以严谨、精炼的事实为依据完成作答。

---

## ✨ 核心特性

- ⚡ **LLM 工具自适应调用**：向 AstrBot 注册 `search_52poke_wiki` 工具，大模型在遇到时效性强或需要核实的内容时可自适应调用。
- 📊 **精确数值与形态提取**：内置专门的种族值模板解析模块，精确提取单项或全项数值（HP、物攻、物防、特攻、特防、速度），支持简称与特定形态（如“路卡z”、“地龙z”、“也龙”）。
- 🎯 **提问意图保留与相关性检索**：覆盖词条全篇可读正文，优先挑选与用户原话直接相关的关键句，避免以词条序言顶替具体问题答案。
- 🛡️ **机器读取保护**：
  - 采用轻量 `prop=revisions` 与原生搜索接口，不使用重负载的 `action=parse`。
  - 同一插件进程内串行请求，从上一次请求完成后至少等待 0.65 秒；较低的配置值会自动提高至此下限。多个实例之间不共享限速锁。
  - 本地正文内存缓存 24 小时、相同搜索结果缓存 10 分钟，兼顾响应速度与资源友好。
- ⚙️ **可视化配置**：支持自定义网络代理、超时阈值、摘录字数上限及原文链接展示。

## 🛠️ 安装与使用

### 安装方式
- **方式一（面板上传）**：在 AstrBot 管理面板的「插件」页面，上传本次提供的插件 ZIP 包。
- **方式二（手动放置）**：将本项目目录复制到 AstrBot 根目录下的 `data/plugins/astrbot_plugin_52poke`，并在面板中点击「重载插件」或重启 AstrBot。

### 使用方法
需要启用 AstrBot 的模型工具调用能力，并使用支持工具调用的模型；插件本身没有独立查询指令，也不绑定特定模型提供商。`search_provider_id` 只用于可选的检索词整理，留空可用。机器人运行环境需要能够访问 `wiki.52poke.com`。

当与机器人对话时涉及宝可梦知识，大模型可按需触发工具：
- *“姆克鹰特防种族值是多少？”*
- *“路卡z物攻有变化吗？”*
- *“密勒顿的特性是什么？有什么效果？”*

## ⚙️ 配置说明

在 AstrBot 管理面板的「插件配置」中可按需调整以下参数：

| 配置键名 | 类型 | 默认值 | 作用说明 |
|---|---|---|---|
| `search_provider_id` | `string` | `""` | **百科检索模型**：可选，指定用于将复杂问题提取为维基检索词的大模型 Provider。留空时使用规则内置解析。 |
| `proxy` | `string` | `""` | **网络代理**：支持传入 HTTP/HTTPS 代理地址（如 `http://127.0.0.1:7890`）。留空则直连。 |
| `request_timeout` | `int` | `10` | **请求超时（秒）**：访问百科 API 的单次请求超时阈值，推荐范围 5~30 秒。 |
| `max_excerpt_chars` | `int` | `220` | **摘录字数上限**：返回给大模型的最大参考字数，可按需控制以优化上下文 Token 消耗。 |
| `append_source_url` | `bool` | `true` | **附带原文链接**：是否在提供给大模型的资料中附带 52poke 词条原文参考链接。 |
| `min_request_interval` | `float` | `0.65` | **请求防频控间隔（秒）**：连续请求百科 API 的全局锁定间隔，避免触发站点频控。 |

`min_request_interval` 从上一次请求完成后计时，低于 `0.65` 的值按 `0.65` 执行，较大的值原样保留。摘录上限以字符数计算，不是 Token 数量。

### 站方读取规则

使用前请核对[机器读取守则](https://wiki.52poke.com/wiki/神奇宝贝百科:机器读取守则)和 [robots.txt](https://wiki.52poke.com/robots.txt)。当前查阅的守则要求间隔超过 500 毫秒，而 robots.txt 写有 `Crawl-delay: 500`；本插件的 0.65 秒下限仅落实前述毫秒间隔要求，不代表已解决两处表述差异。公开部署前应向站方确认适用要求，并按要求调大间隔或暂停使用。遇到封禁应停止请求，不得通过更换代理、IP 或伪装 User-Agent 绕过限制。
